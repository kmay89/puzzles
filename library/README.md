# 📚 The Reading Room

**A block world in your browser, rendered by an engine written from
scratch.** Walk an original library about the freedom to read — or drop
in a Minecraft world of your own and explore that instead. Keyboard,
touch, or a real controller.

No accounts, no ads, nothing tracked, works offline. Part of
[The Solving Room](../). No libraries, no build step, MIT.

## What this is, and what it very deliberately is not

In 2020 Reporters Without Borders and the build studio BlockWorks put a
library inside Minecraft. Journalism that had been censored in Russia,
Saudi Arabia, Egypt, Mexico and Vietnam was reprinted into books on its
shelves, in a game that was not blocked in any of those countries — so
the writing could be read where the websites could not. They called it
**The Uncensored Library**, and it is free at
[uncensoredlibrary.com](https://www.uncensoredlibrary.com/).

This room is **not** that build, and does not pretend to be. Two things
are true and both matter:

- **Nothing of Mojang's ships here.** No game code, no game textures.
  A Minecraft world does not contain pictures — it contains block
  *names*, like `minecraft:oak_planks`, which the game looks up in its
  own assets. So this room looks them up in `blocks.js` instead, and
  paints every texture procedurally when the page loads. What you are
  running is a reader for a documented file format, the same kind of
  thing as a PNG decoder.
- **The building you start in is ours.** It is generated by code in
  `world.js` — a hall, two galleries of shelves, a rotunda — built in
  tribute so there is somewhere to walk before you have downloaded
  anything. Download the real one and point this at it, and the same
  renderer will walk you through the actual thing.

affiliated with, endorsed by, or connected to Mojang or Microsoft.

## What's here

```
index.html    the console shell — markup and all styling
app.js        the conductor: controls, the loop, loading, the shell
nbt.js        Minecraft's binary format, read from scratch: all
              thirteen tag types, gzip/zlib via the browser's own
              DecompressionStream, longs kept exact as BigInt
anvil.js      the .mca region container, and the packed block arrays
              inside it — including the 1.16 change that everybody
              gets wrong (see below)
blocks.js     our own materials, and how a world's block names map on
              to them by word rather than by a table of ten thousand
mesher.js     greedy meshing: cull the faces nobody can see, merge the
              rest into the largest rectangles they will form
world.js      a sparse store of 16³ sections, the tribute build, and
              the importer that turns a region file into blocks
gfx.js        raw WebGL 1: one shader pair, one procedurally painted
              atlas, one buffer per section
sw.js         offline shell (bump VERSION on release)
manifest.webmanifest, icons/
tools/        dev-only, never shipped — see below
```

## Three things worth explaining

**The bit everybody gets wrong.** Since 1.13 a chunk section stores
blocks as a palette plus a packed array of indices. Before 1.16 those
indices run end to end across the whole long array and may straddle the
boundary between one 64-bit long and the next; from 1.16 an index never
spans two longs and the leftover bits are simply wasted. Read a modern
world with the old rule and **nothing throws** — every chunk decodes,
every index is in range, and the world is *plausible and wrong*: walls
half a block out, floors of the wrong material, a library you could
wander for ten minutes before realising none of it is what the builder
made. `anvil-check.js` writes region files with both packings and
compares all 4,096 blocks of a section against what went in. It also
measures the damage: reading a modern chunk the old way puts **4,021 of
4,096 blocks wrong**, silently.

**Why the mesher is arithmetic, not art.** A library is a few million
blocks; drawn as cubes that is tens of millions of triangles and no
phone survives it. Almost all of those faces are buried inside walls, so
they are culled, and what survives is merged into the largest rectangles
it will form — a flat 16 × 16 floor becomes *one* quad instead of 256.
Merging is easy to get nearly right and nearly right looks fine, so the
check is a conservation law: **the total area of the merged quads must
exactly equal the number of exposed unit faces**, on every input. A quad
one block too long breaks it; a gap breaks it; an overlap breaks it.

**Every input is the same four numbers.** Keyboard, mouse, touch sticks
and the Gamepad API all reduce to move-x, move-z, look-x, look-y plus a
jump and a sprint flag, before anything else sees them. That is why a
real controller works without a single special case in the movement
code: plug one in and the sticks, the triggers and the face buttons are
simply there.

## Why it's honest

- **The format readers are proved against independent encoders.** The
  NBT reader is checked against a writer built from the format
  description in `tools/nbt-write.js`, sharing no code with it — a
  parser tested against its own serialiser proves only that two halves
  of one misunderstanding agree.
- **105 checks** across four tools, about ten seconds:
  `node library/tools/check-all.js`
- **The browser check builds a region file in memory and drops it on
  the page**, so the whole path — bytes → NBT → Anvil → palette →
  world → mesh → screen — runs end to end without needing a real save.
- It also caught two things no amount of node testing could. A canvas
  reported a healthy triangle count while showing nothing but sky,
  because the matrix helper multiplied its arguments in the reverse
  order — the world was being drawn correctly to somewhere off screen.
  And the camera and the movement code disagreed about which way was
  forward, so you spawned with your back to the library and walked
  backwards out of it.

## Run it locally

```
cd puzzles
python3 -m http.server 8000
# open http://localhost:8000/library/
```

Before shipping changes:

```
node library/tools/check-all.js       # everything, ~10s
node library/tools/nbt-check.js       # the format, against an independent encoder
node library/tools/anvil-check.js     # both bit packings, block by block
node library/tools/mesher-check.js    # the conservation law
node library/tools/room-check.js      # opens it in a browser and walks it
node library/tools/make-icons.js      # redraws the icons from scratch
```

`room-check.js` needs `playwright-core` (`npm i --no-save
playwright-core`); without it the check says so and exits 0. Nothing it
installs is ever shipped — the room itself has no dependencies at all.

…and bump `VERSION` in `sw.js` so installed visitors hear about it.

## Loading a real world

Any Minecraft Java save has a `region/` folder full of `r.<x>.<z>.mca`
files. Open **Load a world** and drop them in — or the whole folder.
Nothing is uploaded: the file is read in your browser and stays there.

Worlds are big. A single region file holds up to 1,024 chunks and a
build the size of the Uncensored Library is hundreds of them, so the
room reads a handful at a time rather than hanging the tab pretending
otherwise.
